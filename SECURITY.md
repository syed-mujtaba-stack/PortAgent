# Security Policy

## Supported Versions

| Version | Supported          |
| ------- | ------------------ |
| 0.1.x   | :white_check_mark: |
| < 0.1   | :x:                |

## Reporting a Vulnerability

### Reporting Security Issues

**Please do not report security vulnerabilities through public GitHub issues.**

Instead, please report them by emailing [abbasmujtaba125@gmail.com](mailto:abbasmujtaba125@gmail.com).
You should receive a response within 48 hours. If for some reason you do not, please follow up via email to ensure we received your original message.

### When to Report a Security Issue

- You think you discovered a potential security vulnerability in PortAgent
- You are unsure how a vulnerability affects PortAgent
- You think you discovered a vulnerability in another project that PortAgent depends on

### When Not to Report a Security Issue

- You need help applying security-related updates
- Your issue is not security related

## Security Updates and Alerts

All security updates will be released through standard version updates. The latest version will always be the most secure version of PortAgent.

## Security Updates, Alerts, and Notices

Security updates will be announced on the [GitHub Security Advisories](https://github.com/syed-mujtaba-stack/portagent/security/advisories) page.

## Security Disclosures

When security issues are reported, they are handled with the highest priority. The security team will:

1. Acknowledge receipt of the vulnerability report
2. Work with the reporter to understand and validate the issue
3. Release a fix as soon as possible
4. Publicly disclose the vulnerability in the release notes

## Security Best Practices

### For Users
- Always use the latest version of PortAgent
- Keep your dependencies up to date
- Follow the principle of least privilege when setting up API keys and permissions

### For Developers
- Follow secure coding practices
- Keep dependencies updated
- Run security scans regularly
- Never commit sensitive information to the repository
